# Notes for coding agents

AnyRead MD is a Chrome extension (Manifest V3) that reads, browses and edits
Markdown files, and shows CSV, Excel, Word and PowerPoint files Chrome would
only download. It is a fork of md-reader 2.x (MIT). What each folder holds is
in the README ("專案結構", or [doc/en/README.md](doc/en/README.md) in English).

## Set up, build, test

```bash
npx pnpm@9 install --frozen-lockfile   # dependencies, exactly as locked
npx pnpm@9 build:extension             # build into extension/
npx pnpm@9 test                        # unit tests (Node, no browser)
npx pnpm@9 test:e2e                    # browser tests (needs the build above)
npx pnpm@9 test:e2e folder office      # only some browser tests
npx pnpm@9 run build                   # version into the manifest, build, dist/anyread-md-<version>.zip
```

The browser tests load `extension/` into Chrome for Testing, downloaded once
into `tests/e2e/.cache/` (or set `CHROME` to a Chrome for Testing / Chromium
executable; a branded Chrome no longer loads unpacked extensions from the
command line). They open real windows. Their files are made up and written
fresh into `tests/e2e/.work/` on every run. See
[tests/e2e/README.md](tests/e2e/README.md).

## Tests are the minimum, not the finish line

Passing tests only says that what they check still works. Several real bugs
in this project passed every test, because nothing checked for them; they
were found by using the extension. So:

1. **Add a test for what you change.** For a bug, first write a test that
   fails, then fix it so it passes.
2. **Make sure a new test can fail.** Run it against the old code (or break
   the code on purpose) and see it fail. A test that cannot fail checks
   nothing.
3. **Look at the result.** For anything visible, open it in the browser or
   look at the screenshot, in light and dark themes. "Passed" is not enough.
4. **Think through the cases that break things** whenever you touch nearby
   code: an empty folder, the top of a drive, very large files, non-ASCII
   names, dark theme, all five interface languages, Back / Forward, the
   split pane open while Esc is pressed, a file inside the folder page
   versus on its own tab, the pane turned off in Settings.
5. **Do not change a test just to make it pass.** If a test must change
   because the design changed, say why in the commit.
6. **Say what was not verified.** End with the parts no test or check
   covered, so a person can look at them.

## Ground rules

- **Light.** No outside services, analytics or network calls of our own.
  Ask before adding a dependency, and before anything that makes pages
  load noticeably slower; a heavy feature can go behind a setting.
- **Private.** Nothing the user reads leaves the browser. Do not widen
  permissions; web sites stay off until the user turns them on.
- **Licenses.** Only permissive licenses (MIT, ISC, BSD, Apache-2.0); no
  GPL, LGPL or AGPL. Third-party notices are collected at build time.
- **Test files are invented.** Never commit real documents, screenshots of
  real content, personal paths or user names. Fixtures are generated by
  `tests/e2e/fixtures.mjs` and the unit tests.
- **Five languages.** Every text shown goes into
  `src/config/i18n/locale.json` in en, zh-CN, zh-TW, ja and ko.
- **Two READMEs.** `README.md` (Traditional Chinese) and
  `doc/en/README.md` (English) say the same things; change both.
- **Releases.** The version is only in `package.json`; release notes are
  `release-notes/v<version>.md` (Chinese, then English), written before the
  tag. The store listing text is in `store/listing.md`.
- **Commits.** Only when asked. A short subject, then plain sentences or
  bullets on what changed and why.
